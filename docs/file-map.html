PurrSense File Map

Which files are frontend, which are backend, and what each one does. PurrSense is a cat wellbeing app (mood + Feline Grimace Scale pain score) with an Android app and an iOS app that share one Firebase project.

There is no backend server in this repo.

The "backend" is Firebase, a managed cloud service. The repo only contains its configuration (database security rules, Remote Config values). Everything else runs on the phone. The mobile apps contain a client-side logic layer that talks to Firebase and to Gemini, so this page splits the code into three layers instead of two.

Frontend (UI)Screens, navigation, camera/photo picker. Jetpack Compose on Android, SwiftUI on iOS. Design not finalised.
calls ↓
Client logicAI pipeline, prompts, data models, Firestore/Auth/Remote Config access. Runs on the phone but is the app's "backend-facing" code.
network ↓ (Firebase SDKs)
Backend (Firebase)Auth (anonymous), Firestore database, Remote Config, App Check, AI Logic → Gemini in the cloud. Configured by the files in firebase/.

Backend

Firebase configuration

Deployed to the cloud with firebase deploy --only firestore:rules,remoteconfig. Shared by both apps.

RoleFileWhat it does
CLI configfirebase.json Tells the Firebase CLI where the Firestore rules, indexes and Remote Config template live, so one deploy command pushes all of them.
Database securityfirebase/firestore.rules The only server-side access control. A signed-in user can read and write users/{uid}/** only when uid is their own. Nobody can see another user's cats or readings.
Database indexesfirebase/firestore.indexes.json Empty. The app's queries (order by createdAt) use Firestore's automatic single-field indexes.
Remote Configfirebase/remoteconfig.template.json Values the team can change without releasing a new app:
  • cloud_quick_model: Gemini model for the quick read and fallbacks
  • cloud_deep_model: larger Gemini model for the Deep Check
  • grimace_alert_threshold: pain score (default 4/10) that triggers a Deep Check
  • gemini_pain_offset: +2 points added because Gemini under-scores pain
  • cat_id_min_similarity: cosine similarity (0.6) needed to recognise a cat
Client logic

AI pipeline and data access

The code that talks to the backend. Each Android file has an iOS twin that does the same job.

RoleFilesWhat it does
AI "brain"
Androidandroid/…/ai/CatBrain.kt
iOSios/PurrSense/AI/CatBrain.swift
 Every Firebase AI Logic (Gemini) call lives here. Runs the pipeline steps:
  • See: mood + 5 grimace scores from the photo. Android tries on-device Gemini Nano first, then cloud; iOS uses cloud (Apple's on-device model is text-only).
  • Who: which registered cat it is, by comparing image embeddings; falls back to text matching for older cats.
  • Care note: a short owner-friendly explanation, on-device first.
  • Escalate?: a plain rule, pain score + offset ≥ threshold or visible signs.
  • Deep Check: larger cloud model at higher resolution, only when escalated.
  • Trend: summary of recent readings.
Also records where each step ran (on-device / cloud / rules) for the "TwoBrain trace".
Prompts
Androidandroid/…/ai/Prompts.kt
iOSios/PurrSense/AI/Prompts.swift
 The text sent to the models: quick read (JSON with mood and Feline Grimace Scale), identify, care note, Deep Check and trend. Kept short because on-device models accept about 4k tokens in and 256 out.
On-device vision
Androidandroid/…/ai/CatEmbedder.kt
iOSios/PurrSense/AI/CatVision.swift
 Turns a photo into a number vector (embedding) to recognise the cat, plus cosine similarity. Android uses MediaPipe with mobilenet_v3_small.tflite. iOS uses Apple Vision, which also checks there is a cat and crops to it before anything is uploaded.
Data access
Androidandroid/…/data/Repository.kt
iOSios/PurrSense/Data/Repository.swift
 The bridge to Firebase services:
  • Loads Remote Config into an AppConfig, with safe defaults when offline.
  • Signs the user in anonymously.
  • Reads and writes Firestore: users/{uid}/cats/{catId} and …/readings/{id}. Writes aren't awaited so they work offline.
Photos are never uploaded, only structured results and embeddings.
Data models
Androidandroid/…/data/Models.kt
iOSios/PurrSense/Data/Models.swift
 Shapes of the data: Cat, Grimace (5 scores, total, pain score with offset), Mood (positive / neutral / negative), QuickRead, DeepCheck, Reading (what Firestore stores), Analysis and TraceStep.
App start-up
Androidandroid/…/PurrSenseApp.kt
iOSios/PurrSense/PurrSenseApp.swift
 Initialises Firebase and installs App Check (debug provider for the hackathon), which AI Logic requires. On iOS this is also the SwiftUI entry point.
On-device model
Androidandroid/app/src/main/assets/mobilenet_v3_small.tflite
iOSbuilt into Apple Vision
 Binary model file loaded by CatEmbedder to compute cat embeddings on the phone.
Frontend

Screens and app state

What the user sees and taps. Four screens on both platforms: Home, Result, Add cat, Cat detail.

Not finalised

The frontend design is not final. The current screens are a working first version for the hackathon build. Aqil and Ilham will research the frontend design further (layout, visual style, how results and pain alerts are shown) before it is settled. Expect these files to change.
